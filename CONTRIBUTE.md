## How to Contribute

### Reporting Issues

If you encounter any bugs, crashes, or unexpected behavior, please [open an issue](https://github.com/prizrak1609/RocketFS/issues/new) and provide as much detail as possible:
- Steps to reproduce
- Expected behavior
- Actual behavior
- Logs or screenshots if applicable
- Environment (OS, version, etc.)

### Submitting Feature Requests

Have an idea to improve RocketFS? Please [create a feature request issue](https://github.com/prizrak1609/RocketFS/issues/new?labels=enhancement) and describe:
- The problem your feature solves
- How you envision the feature working
- Any alternatives you’ve considered

### Contributing Code

1. **Fork** the repository and **clone** your fork.
2. **Create a new branch** for your work (`feature/awesome-feature` or `fix/important-fix`).
3. **Make** your changes, ensuring you follow the [Coding Guidelines](#coding-guidelines).
4. **Test** your changes locally.
5. **Commit** your changes with clear, descriptive messages.
6. **Push** your branch to your fork.
7. [**Open a Pull Request**](https://github.com/prizrak1609/RocketFS/pulls) against the `main` branch, describing your changes and referencing any related issues.

### Improving Documentation

Help is welcome to enhance or correct documentation. To contribute:
- Update Markdown files in the repo (such as `README.md`).
- Suggest improvements to code comments, especially for complex logic.
- Submit your changes as a pull request.

## Development Environment

- **Languages:** C++, C, QML, CMake
- **Tools:** CMake, Docker, Qt6
- **Recommended IDE**: Qt Creator(but you could use CLion, VSCode, Visual Studio with Qt plugin)

### Setup Steps

1. Clone the repo:  
   `git clone https://github.com/prizrak1609/RocketFS.git`
2. Build Server Docker container
3. Open project in IDE
4. Develop

---

## Coding Guidelines

- Follow common C++ best practices.
- Use consistent code formatting.
- Write clear, maintainable, and well-commented code.
- Add or update unit tests for any code changes.
- For QML: keep UI code modular and reusable.
- For CMake: keep scripts portable and readable.

---

## Pull Request Process

- Ensure your branch is up-to-date with `main`.
- One logical change per pull request (avoid mixing unrelated changes).
- Assign appropriate labels (bug, enhancement, documentation, etc.).
- Reference relevant issues in your PR description.
- Be responsive to code review feedback.
